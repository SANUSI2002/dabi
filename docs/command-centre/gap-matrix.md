## 1. Research — verified capabilities and how they apply to Sabi

Only sources actually read are listed. "Verified" = stated in the source; "Recommendation" = our design choice.

| Topic | Verified capability (source) | Recommendation for Sabi |
|---|---|---|
| Delivery pricing structure | DoorDash Drive charges a **base rate within a distance band plus a per-mile surcharge beyond it, up to a maximum distance**; the fee is fixed at request time ([DoorDash Drive — Pricing & payment](https://developer.doordash.com/en-US/docs/drive/overview/pricing_payment), via search result summary; direct fetch returned 403). | Support base fee + per-km rate + optional distance bands + minimum + maximum distance; fix the price at order creation (snapshot). |
| Fee transparency | Uber Eats itemises delivery fee, service fee (% with min/max), small-order fee and a long-range fee beyond a standard distance ([Uber — Understanding fees](https://www.uber.com/gb/en/blog/understanding-fees-and-arrival-time/)). | Show an itemised breakdown at checkout and on every order; support small-order surcharge and free-delivery threshold as explicit rules. |
| Distance source | Google Routes API `computeRouteMatrix` returns road **distance and duration** per origin/destination pair ([Compute Route Matrix overview](https://developers.google.com/maps/documentation/routes/compute-route-matrix-over)). Distance apps distinguish "by road or straight line" ([Zapiet](https://www.zapiet.com/delivery-rates-distance)). | Record the distance method on every quote (`STRAIGHT_LINE` today; `ROAD` only when a routing provider is configured). Never silently switch methods; if road routing is configured and fails, the quote fails with a clear error unless the configuration explicitly allows straight-line fallback. |
| Refunds | Paystack refunds are created against a transaction reference with an optional amount (partial), are **queued**, and can fail/retry ([Paystack refunds docs](https://paystack.com/docs/payments/refunds/), [support article](https://support.paystack.com/hc/en-us/articles/360009882120); direct fetch 403, content from search summary). | Refunds are records with states (requested → approved → submitted → processed/failed), amount ≤ refundable balance, idempotency key, provider reference; never "mark refunded" without a provider result or recorded evidence. |
| Webhook duplicates | Webhook delivery is at-least-once and unordered; de-duplicate on the provider event id with a unique constraint, recorded in the same transaction as the effect (summary of Stripe guidance via [activepieces](https://www.activepieces.com/blog/webhook-idempotency-how-to-handle-duplicate-events-2026)). | Already done for Paystack (`payment_attempt_events.provider_event_key` unique). Surface duplicates/failures in the Command Centre. |
| Commission & reconciliation | Stripe Connect: the platform's commission is an application fee per charge; reconciliation matches charges, fees and payouts using the same filters/date range/time zone; refunds reverse fees ([Stripe app fees](https://docs.stripe.com/connect/marketplace/tasks/app-fees), [Stripe fees report FAQ](https://support.stripe.com/questions/fees-report-faq), [payout reconciliation](https://docs.stripe.com/connect/supported-embedded-components/payout-reconciliation-report)). | Per-fulfilment commission snapshot (exists), provider earnings = subtotal − commission (+ delivery fee to the courier side), settlement batches that list exactly which fulfilments they pay, refunds reverse commission. Reconciliation report with explicit date range + time zone. |
| Failed delivery handling | Onfleet: failed tasks require a **reason** from a configurable list (recipient unavailable, unable to locate, refused…); dispatchers can force-complete; webhooks on failure ([Onfleet — Complete a task](https://support.onfleet.com/hc/en-us/articles/10373142665364-Complete-a-Task), [Custom completion reasons](https://support.onfleet.com/hc/en-us/articles/16376107034388-Custom-Task-Completion-Reasons)). | Delivery exceptions view: rejected/stalled assignments with reasons, time since assignment, reassignment. |
| Support desk | Zendesk: internal notes are agent-only, never emailed to the requester, cannot be deleted (only redacted by admins); escalation via assignment + priority ([Zendesk help](https://support.zendesk.com/hc/en-us/articles/4408843621530-Using-the-Slack-for-Zendesk-integration); summary via [eesel](https://www.eesel.ai/blog/zendesk-private-comment-to-requester)). | Support cases linked to user/order/appointment, internal notes append-only, assignment, priority, escalation, status history. |
| Admin least privilege | Okta: avoid super admin for routine work; custom roles bound to resource sets; read-only report/log roles ([Okta custom admin roles](https://support.okta.com/help/s/article/custom-admin-roles-a-guide-to-least-privileged-okta-admins), [Okta least privilege](https://sec.okta.com/leastprivilege)). | Split platform roles: Operations, Support, Finance, Clinical oversight, Compliance, Security, Platform admin, Super admin — each a permission set enforced server-side. |
| Audit of record access | HIPAA §164.312(b) audit controls + §164.308(a)(1)(ii)(D) activity review; reviewers independent of those reviewed ([HHS audit protocol](https://www.hhs.gov/hipaa/for-professionals/compliance-enforcement/audit/protocol-edited/index.html), summary via [AccountableHQ](https://www.accountablehq.com/post/hipaa-information-system-activity-review-requirements-frequency-and-compliance-checklist)). Nigeria NDPA 2023 treats sensitive personal data processing as conditional and requires DPIAs for high-risk processing ([FPF — NDPA explained](https://fpf.org/blog/nigerias-new-data-protection-act-explained/)). | Every sensitive read in the Command Centre requires a stated purpose and writes an audit event (actor, time, target, reason); access history visible per patient; audit is append-only. |
| Break-the-glass | HL7 EHR-S FM TI.2.1.2.8: audit every extraordinary access (who, what, when, where, why); FHIR AuditEvent proposal records override start and stop ([HL7 EHRS-FM](https://hl7.org/ehrs/uv/ehrsfmr2/2025May/Requirements-EHRSFMR2-TI.2.1.2.8.html), [FHIR-9167](https://jira.hl7.org/browse/FHIR-9167)). | Emergency access is an explicit, reason-required, time-limited grant (default 60 min), audited at start, use and end. |
| Practitioner licences | MDCN annual practising licences run 12 months from 1 January ([MDCN briefing](https://mdcn.gov.ng/page/recent-news/briefing-note-to-all-medical-and-dental-practitioners-improvements-to-prevent-end-of-year029)). | Credential-expiry alerts for doctors, pharmacies (superintendent + branch licences already stored) and riders. |

## 3. Explicitly out of scope / dependencies (documented, not mocked)

- **Consultation and hospital-plan payments**: no payment model exists for doctor appointments or enrolments, so there are no such transactions, commissions or refunds to oversee. Versioned fee pricing for them is deliberately not built until a payment flow exists (a fee that is never charged would be pretend functionality).
- **Real payouts to providers**: no payout provider integration/credentials (e.g. Paystack Transfers) — settlements are recorded with external transfer references and two-person approval; automatic transfers are a dependency.
- **Road-distance routing**: requires a routing API key (e.g. Google Routes). Without one, pricing uses and labels straight-line distance.
- **Live refunds**: Paystack secret key needed; refunds are submitted only when configured, otherwise remain approved-awaiting-submission with that status shown.
